# Active fluid-domain smoke tests

These tests validate the architectural refactor that separates the fixed numerical box from the active fluid domain. They are not yet liquid-EOS validation cases.

## 1. Generate the reduced-domain initial state

The fixed numerical box remains `Lx=1`, `Ly=1`, but the active fluid top is set to `yTop=0.95`. Generate an initial particle state that already lies inside that active fluid domain:

```matlab
addpath('matlab')

generate_smpcd_state_uniform( ...
    'output', 'initial_state_active_y095.smpcd', ...
    'Lx', 1.0, ...
    'Ly', 0.95, ...
    'Nx', 32, ...
    'Ny', 32, ...
    'gamma', 80, ...
    'kBT', 0.01, ...
    'mass', 1.0, ...
    'type', 0, ...
    'seed', 12345);
```

## 2. Run fixed and slowly moving active-domain cases

```bash
./build/src_mpcd_base examples/params_active_domain_y_top_static.kv
./build/src_mpcd_base examples/params_active_domain_y_top_slow_motion.kv
```

The static case should report constant `fluidYMax=0.95`, `fluidArea=0.95`, and constant mean physical density. The slow-motion case uses

```text
fluidYTop0 = 0.95
fluidYTopVelocity = -0.001
```

with `dt=0.001` and `nSteps=10000`, so `t_end=10` and `fluidYMax_end=0.94`. The expected density increase is therefore approximately `0.95/0.94 - 1 = 1.064%`.

## 3. MATLAB summary validation

```matlab
addpath('matlab')

out = validate_active_fluid_domain_refactor({ ...
    'runs/periodic_base', ...
    'runs/active_domain_y_top_static', ...
    'runs/active_domain_y_top_slow_motion'}, ...
    'labels', {'full box', 'static yTop=0.95', 'moving yTop'}, ...
    'makePlots', true);
```

The validation is intentionally based on `summary_runtime.csv`: detailed fields remain dump/post-processing responsibilities, while the runtime summary records only geometry that cannot be reconstructed from particle dumps alone for time-dependent domains.
