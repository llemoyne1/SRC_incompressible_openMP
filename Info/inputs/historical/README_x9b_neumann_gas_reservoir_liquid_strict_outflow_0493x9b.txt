0493x9b -- Gas virtual pressure reservoir + liquid strict outflow
=================================================================

Purpose
-------
x9a removed the complete MACROSCOPIC reservoir drift vector when the local
coarse state indicated backflow. The 200x400 atomizer test then no longer showed
the x8y/x8z catastrophic backflow/sliding mode, but the liquid still behaved as
if a residual kinetic barrier opposed its exit.

x9b is a deliberately clean species ablation:

  GAS:
    keep the complete x9a virtual pressure reservoir closure.

  LIQUID:
    generate NO virtual-reservoir candidates at a Neumann outlet.
    Physical liquid particles crossing outward are untouched by x9b and follow
    the existing outlet streaming/deletion path (crossing -> inactive).

This tests whether the thermal half-reservoir is necessary for the compressible
gas but inappropriate for the Q6 incompressible liquid.

Important semantic point
------------------------
x9b does not freeze, reflect, modify or pair outgoing liquid particles. It only
removes the exterior source of synthetic liquid particles. The physical outlet
remains an outlet: real liquid particles that cross out of the computational
domain disappear through the existing inactive path.

Environment gates
-----------------
MPCD_CUDA_OPEN_BOUNDARY_NEUMANN_LIQUID_STRICT_OUTFLOW_0493X9B=1
MPCD_CUDA_OPEN_BOUNDARY_NEUMANN_LIQUID_TYPE_0493X9B=<particle type>

The supplied atomizer wrapper sets the second variable from LIQUID_TYPE
(default 1). x9b is enabled only when x9a is already active, so disabling x9b
recovers x9a behavior.

Expected log marker
-------------------
[0493x9b-neumann] mode=gas_virtual_pressure_reservoir_liquid_strict_outflow
    liquidType=1 liquidReservoir=off physicalLiquidCrossing=inactive
    gasReservoir=x9a thermalGasInflow=preserved ...

Apply
-----
From the experimental worktree where x9a is already applied:

  git apply --check /path/to/x9b_liquid_strict_outflow_after_x9a.patch
  git apply         /path/to/x9b_liquid_strict_outflow_after_x9a.patch

Copy the two supplied wrappers to scripts/ if desired, then rebuild with the
normal CUDA build script.

Recommended qualification
---------------------------
Use the same fast 200x400 geometry as x9a:

  CLEAN_RUN_ROOT=1 \
  bash scripts/run_x9b_gas_reservoir_liquid_strict_outflow_200x400.sh

Defaults:
  NX=200, NY=400, Lx=0.78125, Ly=1.5625
  STEPS=1800, DUMP_STATE_EVERY=250, RECORD_EVERY=50

Compare against x9a with the same seed. The key observables are:
  - gas density/outlet cleanliness before liquid contact;
  - whether liquid crosses the outlet instead of accumulating against it;
  - total and per-species active particle counts;
  - liquid ux near the last 5-20 physical columns;
  - any rarefaction layer generated by strict liquid absorption.

If x9b qualifies on the short domain, perform a final non-regression run on the
longer 400x400 domain before considering the closure qualified.
